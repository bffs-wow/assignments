# Raid Assignment Automation

Generates raid cooldown assignments for WoW Classic (Mists of Pandaria) from
RaidHelper signups and Warcraft Logs timelines, and delivers them to the guild's
shared Google Sheets workbook ("AI BFFS SOO Assigns") — whose SOO-Assigns-Import
tab ultimately feeds an in-game WeakAura pack. The workbook is the persistent
store both the raid leader and the app write to.

## Language

### The workbook

**raid sheet**:
The guild's shared Google Sheets workbook (file "AI BFFS SOO Assigns").
Persists the active roster, per-tier raid plans, and the WeakAura-facing
import data. One tab per artifact. Exists in two copies: the production raid
sheet and the test raid sheet.
_Avoid_: "the spreadsheet", "the Google Sheet" (ambiguous — which tab?)

**production raid sheet**:
The live, raid-leader-facing copy of the raid sheet. The app must never write
to it until its output is proven correct; the sheet writer targets only the
test raid sheet during testing and initial release.
_Avoid_: "the original sheet" (unclear)

**test raid sheet**:
A developer-owned copy of the raid sheet used for integration testing and the
initial release. All automated writes go here (via configuration) while the
production raid sheet stays untouched — the write gate is only lifted once
testing is validated.
_Avoid_: "staging sheet", "sandbox"

### Tabs and artifacts

**ROSTER tab**:
The human-edited live roster: per-role rosters (TANKS / HEALERS / MELEE /
RANGED), split groups, and sign-offs. The app normally takes its roster from
RaidHelper instead; this tab is the human-maintained mirror.
_Avoid_: "the roster sheet"

**SOO ASSIGNS tab**:
The live raid plan the raid leader reads during the raid: one section per Siege
of Orgrimmar boss (kill order, spreads, soak/bombard assignments, notes), a
pre-raid checklist (buffs, feasts, addon versions), and the assignment check-in
tracker. Also holds the legacy raid-pack import squares. Distinct from
**SOO-Assigns-Import** — note the space in this name.
_Avoid_: "the import tab", "the assignments tab"

**SOO-Assigns-Import tab**:
The machine-facing tab the app writes to: one section per boss built from a
HEALTH % block and a COUNT block, a row-per-assignment export grid, and the
single import box the RAIDLEAD WA pack consumes. Note the hyphen in this name.
The other raid tiers have hidden sibling tabs with the same shape (TOT-,
TOES-, HOF-, MSV-Assigns-Import).
_Avoid_: "SOO ASSIGNS", "the assignment sheet"

**MoP-Data-Assigns tab**:
The master data tab: the spell table, the role-name bindings with class colors,
and the event key lookups for every tier and boss.

**MoP-Roster-Import tab**:
The "do not edit" tab holding the canonical role-name bindings: a KEY→NAME
pair list plus a copy-paste import string the WeakAura pack consumes.

**TEMPLATE ASSIGNS tab**:
The blank per-boss section template used to stamp out new raid-tier tabs.

### Blocks and the grid

**COUNT block** (formerly "Section 2"):
The assignment rows for one boss — the region after the COUNT header that the
pipeline clears and replaces. Ends where the next boss's HEALTH % block begins.
This is the app's only write surface in the raid sheet; everything else the
sheet owns.

**HEALTH % block** (formerly "Section 1"):
Per-boss health-threshold trigger slots: numbered template rows whose triggering
boss/mob is named in the NPC NAME column. Not written by the pipeline today.

**export grid**:
The row-per-assignment, 13-column grid inside SOO-Assigns-Import: Player,
CD #, BOSS HEALTH / SPELL, COUNT / HEALTH %, PLAYER/CLASS/ALL, TIME, COOLDOWN
SPELL, a spell-icon lookup, an NPC-name column, ADDITIONAL TEXT, OVERRIDE TTS,
CUSTOM NAME, CUSTOM ICON. The Player and spell-icon cells are auto-resolved from
the role-name bindings and the spell table — a writer must not set them
directly. This is the pipeline's write target.

**import box**:
The single WeakAura payload cell in SOO-Assigns-Import that the raid leader
copies into the RAIDLEAD WA pack. Records are `*`-separated, fields
`/`-separated. It uses event keys and spell ids rather than the grid's display
names, and is generated by the sheet itself from the COUNT-block rows and the
event key lookups — never written by the app.

### WeakAura packs

**RAIDLEAD WA pack**:
The in-game WeakAura pack (a.k.a. "Raid Assignments"; the TotalAssignments
family) that consumes the import box. The pipeline's ultimate consumer.
_Avoid_: "Tot Assigns", "TotalAssignments" (legacy names)

**raid-pack import string**:
The comma-joined green-square payloads in SOO ASSIGNS (and the T15 tabs)
consumed by the legacy Fojji "Raid Pack" WeakAura (kill-order and assigner
strings, `{rtN}`-group strings). A different artifact and a different WeakAura
from the import box.

### Events, keys, roles

**event** (grid: BOSS HEALTH / SPELL value):
A trigger point an assignment keys on: a boss ability, phase marker, encounter
start, or health threshold (e.g. "Encounter Start (IMM)", "Swelling
Corruption", "Health % (FAL)").
_Avoid_: "boss ability" (timeline term), "trigger" (WeakAura-internal)

**event display name**:
The human form of an event as written in the export grid ("Swelling
Corruption", "Encounter Start (IMM)").

**event key**:
The machine form of an event as used in the import box
("IMMERSEUS_SWELLING_CORRUPTION", "FALLEN_ENC_START").

**event key lookup**:
The per-boss mapping between event display names and event keys. Held in
MoP-Data-Assigns as one pair of columns per raid tier (a display-name column
plus a key column). The sheet remains the canonical source of truth for the
event vocabulary.

**event vocabulary**:
A boss's closed list of valid event display names, as written in the sheet's
display-name column (e.g. for Siege of Orgrimmar, column V of MoP-Data-Assigns
in a `SOO_<BOSS>`-headed block: `Encounter Start (X)`, `Health % (X)`, then the
ability/phase events). Case and suffixes are significant — `Death From Above
(BLA)` and `Death from Above (PAR)` are different events. The generator must
only emit events from this vocabulary; the app holds a baked snapshot of it
for Siege of Orgrimmar in `src/data/soo-encounters.json`, to be refreshed from
the sheet when the owner changes events (see ADR-0001).

**role tag**:
The abstract roster slot an assignment targets ("PROTPALA1", "DISC3", "ALL",
"MELEEDPS", "RANGEDDPS"). The sheet's PLAYER/CLASS/ALL value, the code's
`roleTag`.
_Avoid_: "role key", "spec"

**role-name binding**:
The mapping from a role tag to the player who fills it. Maintained in
MoP-Roster-Import for the sheet; derived from RaidHelper signups by the app's
roster mapper. The export grid resolves the Player cell from it.

### Spells and assignments

**spell table**:
The canonical spell name → id → icon list (MoP-Data-Assigns; mirrored in the
app's `mop_skills.json`), including the raid cooldowns and the literal
"Custom Spell Assignment" placeholder.

**occurrence** (grid: COUNT / HEALTH %):
The ordinal cast(s) of the event an assignment covers. A single number, or a
comma list ("1,4") letting one row cover several casts. In HEALTH % blocks, the
trigger threshold instead.

**custom assignment**:
An assignment whose COOLDOWN SPELL is the literal "Custom Spell Assignment"
(there is no built-in cooldown behind it): the real spell name is carried in the
OVERRIDE TTS cell and its icon, when known, in the CUSTOM ICON cell. The CUSTOM
NAME cell is unused in practice.

**assignment**:
One deliverables row: the event (or health threshold), occurrence, role tag,
time relative to the event (negative = before, fractional allowed), the spell or
skill, an optional note, and a spell id.
